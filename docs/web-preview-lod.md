## Camera-driven display (tasks040/046)

[Task046](tasks/046-rendering-optimization.md) supersedes task041's opt-in default: camera-driven native rendering is now **on by default**, with a hard 3M resident-point ceiling. The previous sampled overview (50k/depth3 initially) plus exact startup street crop remains an explicit opt-out; orbit/zoom in that legacy mode does not request adaptive data. A single **Camera-driven detail** checkbox lives inside the existing collapsed **Scene tools → Display quality** section, with no added toolbar/panel. The old sample budget/depth controls remain when off; adaptive tuning appears only while on. Switching on cancels/releases retained crop, then streams **additive native Potree nodes** selected by camera/frustum, distance and projected node diameter; switching off disposes native requests/caches/geometry and restores the street crop. Parent payloads remain alongside children; nearest visible nodes refine to leaves subject to the resident budget. Loaded native chunks replace the fallback visually; off-plan chunks and their exact pick caches/GPU geometry are released.

**Scene tools → Display quality:** full detail within 0–200m (default30m); distant detail Coarse/Balanced/Fine/Very fine (160/80/40/20px, default80px); point budget500k/1M/2M/3M (default3M); opaque circular point splats2–6px (default4px). Changes apply without reloading the scene. The budget can prevent full nearby detail; the panel reports “Point budget reached,” never whole-cloud/full-detail completion. Manual box/window full-resolution selection and harness observations remain independent; manual crops retain their existing uncapped memory behavior.

The browser uses one physical adaptive request at a time, a150ms camera throttle, sub10cm pose-grid suppression plus refinement/frustum hysteresis, no extra unbounded payload cache and generation/abort gates. Camera motion preserves useful in-flight requests; responses are admitted only after replanning against the newest view. Native nodes pack into at most23 dense GPU batches at3M points; bulk eviction compacts once per affected batch. Demand rendering skips settled idle draws (the lightweight animation/control loop remains active). Retained coarse ancestors remain visible. Errors latch with an explicit Retry action, not a request loop. Native points retain original binary64 positions and source keys for picking/overrides; screenshot coverage records actual native names/settings/counts and invalidates on chunk or quality changes.

Fixed local-only APIs: `GET /datasets/toronto3d/display-hierarchy` returns `{dataset,nodes:[{name,count,bounds}]}`; `GET /datasets/toronto3d/display-node?revision=HEX&name=r012` returns all original decoded positions/RGB/source IDs/labels in that node. Cubic root bounds enclose (need not equal) occupied data bounds. Catalogs follow all hierarchy proxies, validate full point totals and cache by revision plus physical identity. Limits:100k nodes,8MiB hierarchy reads,10k chunks, depth24,65,536 points/4MiB raw payload per native node,16MiB serialized response,15s server deadline; client catalog limit8MiB and binary node response2,244,624 bytes,20s request deadline. The browser requests `&format=binary` with MIME `application/vnd.spatial.adaptive-node`: bounded metadata plus34 bytes/point, preserving binary64 coordinates, source keys and semantic labels. JSON remains available for independent inspection. Actual artifact:30,168 nodes/78,320,210 points; catalog5.2MB, largest node34,401 points. Old sample limits remain unchanged. No new raw asset/range/path endpoint, semantic index preparation, geometry authority or provider calls.

Current actual-cloud browser verification: build first, then `node --import tsx scripts/browser-adaptive-display-smoke.mjs http://127.0.0.1:9222 /tmp/task046-browser`. This owns an ephemeral backend/preview and new tab in existing Chrome only. It checks default adaptive binary rendering, point sizes/batches/idle draws, exact picking, capture coverage, desktop/mobile/error recovery, explicit legacy fallback and rapid cancellation. Task046 records current results; historical legacy street scripts require explicit adaptive opt-out.

## Run

Use Node 22 and pnpm 10.34.6:

```sh
pnpm install --frozen-lockfile
pnpm dev
# Open http://127.0.0.1:5173, choose “Toronto3D preview”.
```

The synthetic fixture needs no dataset. Toronto requires the prepared artifacts from [preprocessing](toronto3d-preprocessing.md): `data/processed/toronto3d/prepared/manifest.json` and `octree/{metadata.json,hierarchy.bin,octree.bin}`. The current combined dataset has 78,320,210 points. The viewer never preprocesses or writes these files. Do not move raw data into the web public directory. No data is bundled into the web build.

For the built viewer, run both `pnpm --filter @spatial/server start` and `pnpm --filter @spatial/web preview`. Development and preview proxy `/datasets/` to the loopback server on port 3001; no CORS is enabled. Missing, malformed, unsupported or symlinked assets yield a sanitized 503 and a visible loading/error status. Start the server/check prerequisites, then use the respective Reload button. Two concurrent dataset operations are allowed; rapid cancellation may briefly yield 429; retry/reload rather than growing an unbounded queue.

## Independent settings and actual outputs

- **User display:** default camera-driven native rendering above; radius/detail/resident-budget/point-size controls stay inside collapsed scene tools. Explicit opt-out restores sampled budgets10k/50k/100k and depth0–3 with the exact startup street crop.
- **Harness input:** budgets 256/1024/4096, maximum depth 0–3. A separate request/channel creates a concrete `PointObservation`; Download exports its complete JSON, not just slider values. It does not borrow the display buffer or camera. Changing display settings never changes harness settings, hash or observation; changing harness settings never changes the display settings or buffers.
- **Full-resolution projected window:** hold Shift before left-button down, drag a rectangle (at least 4 CSS pixels in each direction), then release. A yellow translucent overlay shows the drag. The gesture suppresses OrbitControls; ordinary drag still orbits. Release automatically loads every stored point within the frozen screen rectangle's **camera volume**, including points behind visible surfaces. Perspective cameras produce a truncated frustum; the projection helper also supports an orthographic prism. Six inward local-meter planes are derived from the cropped camera projection × inverse camera world matrix, not from an arbitrary world-axis box. Depth is the current camera near/far interval (viewer 0.1–10,000m) intersected with dataset position bounds. It is not a surface-depth pick and has no hidden thickness. Camera position/orientation are frozen into planes at release; later orbit/zoom does not resample or alter that volume. Reload projected window repeats that frozen query. A thin accidental drag does nothing; a tiny Shift-click places the existing box on a visible overview/detail point.
- **Full-resolution axis-aligned box:** yellow wireframe with local-meter center and positive XYZ dimensions. Use tiny Shift-click or Box at view target to place it; Frame box zooms to it. Load full resolution in box explicitly streams every stored point within inclusive bounds. Editing any box field cancels/clears detail and returns from projected-window mode to AABB mode. Example populated box: center `[278.715, 505.852, 139.662]`, size `[5,5,5]`.
- **Progress and independence:** both full-resolution workflows traverse all intersecting stored ancestor/descendant payloads and nested hierarchy proxies, with no total point/source-work/deadline cap and **no downsampling**. Bounded batches accumulate independent GPU chunks; the dim sampled overview remains for context. Counts are explicitly **partial/incomplete** until an end event certifies the whole selection. Empty complete selections report zero. Cancel loading retains already loaded partial chunks and labels them incomplete; Clear aborts, releases detail and restores overview opacity while retaining the selection. Failed/interrupted/resource-exhausted streams retain clearly labelled incomplete detail, never a misleading complete sample. A selection is disposable display state, not an authoritative CAD entity or geometry edit. Harness settings, sample hash/provenance and buffers remain independent.
- **Selection feedback / actions:** the selection summary names axis-aligned box vs frozen projected camera volume and displays local-meter bounds. Projected bounds are explicitly the dataset clipping extent, not an AABB approximation of the frustum. During streaming, loaded/scanned counts and source bytes report actual work; the selected total is unknown until completion, so no percentage/ETA is fabricated. Stable live-region status changes at phase boundaries, not on every batch. Only successful validated transport completion marks counts complete. Cancel is available only while loading; it retains incomplete detail. Clear is available while loading or with retained detail and keeps the selection. After cancellation/error, Retry same selection clears old partial detail and repeats the frozen window or unchanged box. Viewer/GPU failure reports error, not user cancellation; reload the scene before retrying. Large uncapped resource warning remains visible; no automatic caps/downsampling were introduced.
- Each output has its own cancellation generation and AbortController. Superseded responses cannot publish, even if transport cancellation is ignored. Scene switching aborts all three channels and disposes controls, animation, geometry, material, renderer, resize observer and canvas.

Harness observations contain local XYZ, RGB bytes, Toronto semantic `scalar_Label`, and provenance pairs `(source_file_id, source_row)` (file IDs 1–4 map L001–L004, zero-based source rows). Other scalar attributes are deliberately **omitted**, not silently zero-filled; in particular source intensity may be nonfinite. The result also includes requested budget/depth, actual/candidate counts, ordered node IDs, source bytes read, algorithm ID, sample SHA256, dataset identity/revision, local bounds and coordinate metadata. It is a dataset observation, not a `ProjectState` geometry edit; there is no invented project geometry revision.

`PointObservationSource.observe(lod, signal)` in `@spatial/agent-harness` is the renderer-independent product boundary. The server's `PotreeDataset` concretely implements it with harness caps; HTTP clients use the fixed-purpose observation endpoint. There is no model caller yet.

## Sampling and reproducibility

Algorithm `potree-bfs-even-v1` includes all real nodes at levels **0 through depth**, ordered breadth-first and child index 0–7, from the first hierarchy chunk. Concatenate those nodes' stored point order; select `floor(i * candidateCount / actualCount)` for `i = 0..actualCount-1`. Thus count is `min(budget, candidateCount)`, with no random seed or camera dependence. Higher depth adds finer candidates, but independently spaced subsets are **not necessarily nested**. Potree's Poisson hierarchy supplies the coarse spatial coverage; this is not a statistically unbiased sample of all 78M points.

The supported artifact is **uncompressed interleaved Potree 2** only. For the sampled LOD endpoints, proxies at requested depths are rejected; deeper hierarchy chunks are not followed. The independent full-resolution selection stream follows all intersecting proxies. It is user-triggered projected-volume streaming, not continuous view-dependent LOD: no screen-space error metric, frustum prioritization or semantic filtering. Current depth populations (cumulative): 2,339 / 9,245 / 36,867 / 139,241.

Artifact revision is SHA256 over raw prepared metadata, manifest, first hierarchy chunk, and octree size/mtime. It detects normal local artifact replacement but is **not a full octree content-integrity hash**; copying a dataset may alter it. Preserve the prepared artifacts to reproduce the same observation ordering; rerunning the concurrent converter need not preserve order. `sampleHash` is SHA256 over the deterministic JSON object `{positions, colors, sourceIds, labels}`. It certifies equality of these bounded outputs, not the dataset or CAD validity. Existing full preprocessing validation remains separate.

Coordinates are meters, right-handed Z-up, translation-only `world = local + [627285, 4841948, 0]`. Decode local `int32 * scale + metadata.offset` before rendering; never add the large Toronto origin to GPU positions. Bounds for framing come from the position attribute's actual min/max, not Potree's padded cubic octree box. No CRS reprojection or independent CRS certification. RGB is converted from source sRGB to linear Three vertex colors for rendering; exported RGB remains bytes.

## Security and explicit caps

The loopback HTTP service exposes only:

```text
GET /datasets/toronto3d
GET /datasets/toronto3d/observation?purpose=display&budget=50000&depth=3
GET /datasets/toronto3d/observation?purpose=harness&budget=1024&depth=2
GET /datasets/toronto3d/crop?minX=276.215&minY=503.352&minZ=137.162&maxX=281.215&maxY=508.352&maxZ=142.162
# Projected selection additionally supplies planes=URL-encoded JSON of six [nx,ny,nz,constant] arrays.
```

No user-controlled filesystem path, raw asset route, write method or byte-range endpoint exists. `Range` headers return 416 (including malformed/multi-range values); unknown/duplicate query keys, nonintegers and out-of-range settings return 400. Unknown assets/methods return 404. Loopback Host and HTTP Origin allowlists reject DNS-rebinding/foreign-origin dataset requests. Constant asset paths are realpath-checked and opened read-only with `O_NOFOLLOW`; symlinked assets/intermediate directories are rejected. The root is source-relative, not dependent on the shell working directory. The optional server constructor path exists only for local tests, not as an HTTP parameter.

Sampled metadata/LOD limits (unchanged; NOT full-resolution total limits):

- Each JSON metadata file ≤64 KiB; first hierarchy chunk ≤64 KiB (22-byte records).
- Each selected node ≤4 MiB; all selected point payloads ≤16 MiB; bounded safe integer offsets and file ranges validated before allocation/read.
- At most 100k displayed or 4096 harness points; at most depth 3. No complete octree read/download.
- At most two active server operations; sequential node reads, one node buffer at a time. The actual maximum supported depth reads 7,660,191 source bytes including the first hierarchy chunk; the default 1024/depth2 harness reads 2,029,456 bytes.
- Browser response streaming stops above 16 MiB before JSON parse. Arrays and GPU buffers are bounded by point counts. Bounded serialization and temporary JS/typed-array copies mean process memory exceeds raw payload bytes; these are algorithmic caps, not a measured RSS ceiling.

Full-resolution stream safeguards/resource reality (task005; sampled limits above unchanged):

- **No arbitrary total point, payload/source-byte, hierarchy-work or processing-time cap.** Valid nodes larger than 4MiB are split into point-aligned reads ≤4MiB, one payload buffer at a time. Hierarchy chunks remain ≤64KiB, 22-byte records, supported depth ≤24. These per-format/read protections reject unsupported/corrupt structures rather than sampling.
- The pull-based async generator yields NDJSON `start`, ordered `batch` and terminal `end` events. Each batch covers ≤8192 decoded source points (and ≤8192 selected points), including empty progress batches. HTTP waits for socket drain before pulling more; the browser awaits each batch's GPU publication/paint opportunity before consuming further. There is no combined response body, all-point JavaScript array, giant JSON, or point-sized server accumulator. Browser parser bounds each line to 2MiB; GPU position/color allocations are bounded per chunk. Each GPU chunk accumulates until Clear/scene disposal. **The total GPU/browser memory is not bounded**: large selections can exhaust it or take a long time. Clear/shrink/retry after failure; there is no automatic reduced sample or promised measured RSS ceiling.
- Depth-first proxy traversal retains at most a chunk's queue and pending proxy widths per supported level, plus a pair of safe ranges per visited chunk/node for cycle/overlap checks. Range bookkeeping grows with file hierarchy, not selected points. Safe offsets/file sizes, record count/children, proxy/root agreement, repeated/overlapping chunk and selected payload ranges are validated. Errors discovered after earlier streamed batches mark the result incomplete; they cannot retroactively make those batches complete.
- Nominal child boxes use X/Y/Z bits 4/2/1. Conservative node pruning expands boxes by one quantization step and tests each plane against the box's support vertex. Exact point membership requires inclusive AABB membership plus all six signed plane distances ≥0 (1e-9m numerical tolerance for inclusive floating-point plane boundaries, not a visible thickness or selection AABB approximation).
- Input URL ≤4096 characters, exactly six finite bounds and optional six normalized inward planes; coordinate/plane coefficient magnitudes <10 million, positive AABB dimensions. Same fixed paths/loopback origin/no-follow/Range rejection. Shared two-operation cap includes metadata, samples and streams; no queued requests. Disconnection/cancellation stops future traversal/read/decode/publication. Cancellation is checked between bounded reads and every ≤8192 decoded points with event-loop yields; an already-running OS read, browser frame, or GPU command is **not instantly interruptible**.
- Browser validates start identity/coordinates/selection, bounded point/color arrays, exact membership, sequence/count/monotone stats and terminal completion; aborted/stale channels cannot publish further. GPU context loss/resource allocation failure is shown explicitly. Two metadata reads ≤64KiB each remain additional to reported hierarchy/payload source bytes.
- Only the terminal `end` has `complete:true`, meaning every stored point in that requested volume was visited. Earlier chunks/counts, cancelled/failed selections, and interrupted HTTP streams are never complete. Algorithm `potree-inclusive-volume-v2`; SHA256 covers the selection followed by deterministic ordered bounded batch `{positions,colors}` encodings (including empty batches), not legacy task004's monolithic hash. No harness labels/provenance/geometry revision are invented. Existing artifact fingerprint limitations remain; this is not an integrity audit.

Prepared data should remain immutable while serving. The adapter does not lock against a trusted local process rewriting dataset contents or guarantee adversarial concurrent-filesystem integrity. It does not replace the independent full preprocessing audit.
